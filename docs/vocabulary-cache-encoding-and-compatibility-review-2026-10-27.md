# 缓存编码优化与近期改动兼容性审查

## 本轮已批准设计及执行

用户批准：避免为超过既有缓存预算的大结果完整编码；不增加缓存范围、不截断返回、不修改前端，验证后提交。

- [x] 新增失败测试：UTF-8字节边界、转义字符、dataclass不深复制、超长字符串分块、完整返回不发送Redis。
- [x] 在cache.py新增bounded_encoded。按需缓存直接遍历原对象，仅累计预算内JSON片段；单次最多转义1024个字符，嵌套超过64层或非支持类型跳过可选缓存。不先调用jsonable_encoder或asdict复制完整响应。
- [x] store仅在按需缓存使用有界编码，超限立即返回；永久默认项沿用原编码器及无单项限制行为，Lua版本校验和LRU准入保留。
- [x] 对真实entries、standard-words、map-points、map-items结果逐字段验证JSON等价；同步/异步缓存调用均验证完整原对象返回。
- [x] 将原型基准改为调用生产实现，执行实际数据测量、相关回归与自审，然后按用户要求提交。

没有新增线程、并行任务、服务、磁盘暂存、数据库索引或结果缓存。查询仍走已有准入限制；缓存编码继续在已有工作线程路径执行。编码片段空间随配置的max_bytes增长，而非随完整结果增长；原查询结果和最终HTTP编码仍有各自的内存成本。超大字段也不会先一次性转义；默认缓存不适用此边界。

超过预算原来就在Lua中拒绝，现提前拒绝，不改变是否缓存这类结果。按需缓存支持普通字典、list/tuple、基础JSON标量和查询dataclass；未来如引入其他类型，会跳过可选缓存并照常返回，不能宣称所有任意Python对象均维持缓存命中率。字典键顺序不参与缓存值语义，数组顺序不变；缓存键仍用原规范化编码，未更改命中身份。

本机只读95,003条词条，39,965个归一组。生产编码实现，5轮中位数，原/新编码交错执行。只测缓存准备，不含SQL、Redis网络、HTTP校验/编码及前端渲染。

完整39,965组的单次tracemalloc测量：原编码额外Python分配峰值27,819,916字节，本轮1,092,526字节。结果已在测量前生成；这不是进程RSS或生产整机内存。永久项沿用原路径，无实质速度变化；小型按需项逐片段遍历有额外开销，不能把大结果收益套用到所有请求。本轮不承诺生产延迟或吞吐指标。

14项编码测试通过，使用仅回环绑定、禁用持久化的隔离Redis。全部vocabulary加地名资源/路由/索引脚本/SQL线程回归471项通过，排除此前已在基线复现的10项失败，无跳过项；没有接触生产Redis或数据库。

## 近期改动审查范围

从11f807f之后的性能修改审查：40a267f、1cea0f5、20bf8f8、820e177、0e55834及本轮。7ebdbc0只有磁盘方案文档，不代表查询已使用该实现；更早的功能开发不包含在“性能优化无语义变化”的结论内。

### 正常成功请求：已验证等价的部分

- 词表SQL按筛选条件选择路径、计数去除无用JOIN、先分页再关联地点、地图先聚合：保留孤立词条、同名不同用户身份、地点元数据过滤、分区过滤、简繁匹配、排序及精确total。限定条件的JOIN仍在筛选发生之前。
- 标准词游标读取、堆选择、简繁转换LRU：没有提前SQL LIMIT归一候选；有限列表保持原排名，全量模式完整返回，仍需保存全部分组。
- 预热按需等待、1000项复用100项、后台忙时退让、分步清理：不改变7份默认缓存内容；忙时默认缓存就绪时间可能延后，在线请求仍可按既有回源路径获取结果。后台约1秒重试，异常沿用5/15/60秒退避；不自动重试写操作。
- 上传分批解析/插入、限制旧日志快照物化：不减少真实导入或删除数量；删除日志500条上限是原有规则。导入仍为一次事务，不按批部分提交。
- 导出临时文件：下载文件名、表头及全部行保持；传输方式和响应头可能不同，文件字节不承诺相同（XLSX有生成时间等内容）。
- 地名普通全量JSON流：结果集合及顺序保持，limit=0没有新增数量或总执行时长限制。正常完整接收后，前端现有JSON解析方式可继续使用。

这表示现有覆盖场景的字段和值等价，不是对任意未来数据、并发写入、生产网络及所有调用方的绝对保证。

### 确认存在的可观察变化

|范围|变化|现有调用方影响|

|批量替换|验证移到新写事务之前，期间其他连接提交会返回409并回滚|需重新预览后重试；相同数据库内无关提交也可能触发这一保守检查|

### 前端只读核对

词表页面仍请求标准词1000项；本轮未改请求或响应模型、权限、可操作对象和实际写入规则。

资源保护、冲突检查和异常传输边界应作为明确的行为变化保留说明。部署层代理超时仍由原部署配置决定，后端没有新增词表执行30秒后强杀规则。

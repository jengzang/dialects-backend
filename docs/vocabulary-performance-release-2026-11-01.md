日期：2026-11-01。基线 `29ebfa0`，本地 `dev` 分支；本轮实现、测试、基准测量均在本地完成，没有连接或改动服务器，没有创建分支，没有修改前端、数据库结构或服务配置。

## 1. 已提交的四个方向

| 提交 | 端点 / 场景 | 实际改动 |
|---|---|---|
| `80d9a94` | search/entries：指定普通地点，搜索方言词，或标准词+方言词，首页计数缓存未命中 | 先取一页；不足一页时由完整页内容推导精确总数，省一次 COUNT。满页则执行精确 COUNT。读 SAVEPOINT 保证页与计数使用同一 SQLite 快照。缓存命中仍直接复用总数。 |
| `7716069` | standard-words：同类地点和内容筛选 | 通过现有地点身份索引遍历目标地点词条，再聚合；仅标准词的原有覆盖索引路径保留。 |
| `6fb221c` | standard-words：各种筛选、包括无关键词全量 | 单一地点、单一词形先用标量保存；出现不同地点或词形时才分配集合、字典，减少每个归一词组的对象成本。 |
| `403dccf` | map-points：全域、普通关键词、标准词/方言词/两者 | 内容扫描后分组，减少按地点索引遍历造成的回表。先探测最多 128 条近期记录，命中率达到 75% 则保留原分组路径，避免高命中词的已知退化。 |

普通关键词指没有 SQL LIKE 通配符等需要回退的形状。地点元信息、省市、区域、通配符、重叠条件等未验证适用的路径保留原逻辑；不会因为选择字段数量相同就套用同一计划。`definition` 是查询字段名“标准词”，`headword` 对应“方言词”。

没有新增标准词结果缓存、应用层磁盘聚合、线程、worker 或后台任务。没有给完整查询、聚合或地图输出加截断；标准词 `limit=None` 仍返回所有词组。原有前端请求、响应字段、精确计数、排序、简繁匹配和用户操作保持一致。

## 2. 测量方法与可信边界

- 输入为只读本地数据库；仅离线副本用于扩展数据。当前集 95,003 条词条、39,965 个归一词组；行增长集 475,015 条、词形不变；词形增长集 475,015 条、199,825 个归一词组。另有 95,003 条的高命中合成集，“共同”匹配绝大多数词条。
- 容器限制为 2 CPU、2 GiB、无 swap；核验 `cpu.max=200000 100000`、`memory.max=2147483648`、`memory.swap.max=0`。单次串行执行，不模拟并发流量。
- **服务函数**完整调用在 Linux amd64 镜像上执行，宿主为 Apple ARM，存在架构模拟。每项每版本独立进程，时间取 5 次调用中位数；包含首次调用，原始首次耗时另存。它不是 HTTP 请求计时，不含鉴权、真实 Redis、排队、网络。
- **原生 SQL**另用 ARM Linux / SQLite 3.46.1 回放真实 SQL，一次预热、7 轮交替执行，取中位数；包含探测查询。它没有 Python 聚合和序列化成本。
- RSS、Python tracemalloc 与时间分别测量，避免测量工具影响计时。RSS 是只导入查询所需模块的进程历史峰值，不是完整 Gunicorn worker；tracemalloc 不包含所有 SQLite/OpenCC 原生分配。
- 共 172 组服务函数前后配对（83 时间、83 RSS、6 Python 内存）和 83 组原生 SQL 配对。响应摘要均一致；entries 额外取消分页读取每一条匹配记录，核对完整有序结果与精确 total，验证在计时后执行。
- 非地图测量使用最初第四次提交源码；后续仅地图函数变化，AST 已核对其余函数一致。最终源码 SHA256：`0d039679778bce0c630c71663314ccdaf19f8ad9c9f7f4b63b445ce7a6d47712`。

这些数据可以说明计划和对象分配的相对收益，不能直接承诺线上五六秒会变为多少，也不能预测生产吞吐容量；生产 CPU、磁盘、热缓存、worker 和并发竞争不同。

## 6. 资源、并发与取舍

- 三个 SQL 方向的 RSS 基本不变。例如地点 entries 75.66→75.70 MiB，地点标准词 75.43→75.71 MiB，全域标准词地图 75.70→75.81 MiB。内存主要收益来自标准词分组对象压缩。
- 原有 heavy=2、expensive=1 的资源上限保留；没有增大线程池或创建额外常驻服务。热点计算合并、缓存失效和失败重试策略没有新增变化；本轮未引入自动重试。
- entries 缓存未命中的读 SAVEPOINT 可能持有到回退 COUNT 完成，用于一致性。并发 WAL 写入已做本地回归；不能把读事务理解为零锁或零 I/O 成本。
- SQLite 为 GROUP BY / ORDER BY 自主管理的 TEMP B-TREE 仍可能存在。本轮没有应用磁盘中间聚合，也没有调整 temp_store。高命中标准词的一次 RSS 测量中，进程 `write_bytes` 从 4,104 增到 1,482,760 字节，`cancelled_write_bytes` 为 1,478,656；这是**查询进程总 I/O 差值**，不能精确归属某个临时 B-tree，但说明新计划可能增加 SQLite 临时写入。这一取舍随候选分布变化，需明确保留。
- 首轮完整测量批次 cgroup 峰值约 692.9 MiB，最终地图批次约 209.4 MiB，均没有 OOM。它们包含父子进程和计时之外的结果校验，只代表对应测量批次，不能拿来作为单请求或完整线上 worker 的内存承诺。
- 任意子串 `%关键词%` 仍不能靠普通 B-tree 精确定位；本轮减少重复扫描和不合适的遍历，未改变匹配语义。

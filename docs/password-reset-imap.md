# QQ 邮箱自动找回密码

本功能使用 `2639548777@qq.com` 收取用户主动发送的邮件，通过 IMAP 只读获取原始邮件，并独立验证 DKIM。系统不发送邮件，不需要 MX、SMTP 收信服务器或自动转发。

## 开启方式

后端运行环境需要 `requirements.txt` 中的 `dkimpy==1.1.8`。本次已获用户授权在本地虚拟环境安装；生产环境仍需将该依赖纳入正常发布流程。

给现有后端进程配置以下环境变量，授权码通过部署平台的机密配置或权限为 `600` 的外部环境文件提供，禁止提交到 Git：

```text
PASSWORD_RESET_ENABLED=true
PASSWORD_RESET_IMAP_PASSWORD=<QQ 邮箱 IMAP 授权码>
```

账号和服务器固定为 `2639548777@qq.com`、`imap.qq.com:993`。配置后重启原有后端服务，现有 APScheduler 会注册每 30 秒执行一次的任务；不新增守护进程。不开启时，申请接口返回 `503` 和 `password_reset_unavailable`，前端显示对应语言的不可用提示。

服务器需要能访问公网 TCP 993 和 DNS，不需要开放入站 25 端口。不要配置自动转发，也不要对用户申请自动回复。

## 实际流程

1. 网页填写登记邮箱、新密码及确认密码。
2. `POST /api/auth/password-reset/requests` 返回申请编号、1800 秒有效期和收件地址。用户不存在时返回同样结构。
3. 用户从登记邮箱直接发送邮件，主题为 `RESET-REQUEST`，纯文本正文单独一行为 `RESET-REQUEST: <网页提供的申请编号>`。
4. 后端独立核验完整邮件签名，要求唯一发件地址、DKIM 签名通过、签名域与发件域完全一致，并且不使用仅覆盖部分正文的 DKIM 签名。
5. 只有签名、登记邮箱、有效期、申请状态和原密码快照均匹配，才在事务中更换密码、撤销会话与刷新 token、使同账号其余待处理申请失效。
6. 用户返回登录页面，用自己填写的新密码登录；没有状态轮询接口，也不会收到系统确认邮件。

邮件中不包含密码。申请阶段不改变原密码，不取消其他有效申请；成功后清除同账号申请保存的密码哈希。账号状态必须为 `active`，登记邮箱不能在申请后变更。

无法使用登记邮箱、邮件不具备所需签名或处理失败时，联系 QQ：**2639548777**。第一版采用严格域匹配，部分使用子域签名的邮箱可能无法自动找回，转人工处理。

## 三语接口契约

后端返回固定错误码，前端负责简体、繁体和英文显示，不直接呈现后端英文异常文本。

| 状态码 | `detail.code` | 含义 |
| --- | --- | --- |
| 503 | `password_reset_unavailable` | 未开启自动收信 |
| 429 | `password_reset_rate_limited` | 申请限流或哈希处理繁忙 |
| 400 | `password_reset_invalid_password` | 密码不符合要求 |

请求字段格式错误仍采用 FastAPI 原有 422 响应，前端显示本地化通用失败提示。成功接口仅返回机器字段 `request_id`、`expires_in`、`recipient`，不返回固定语言文案。

## 资源与可靠性边界

- 复用现有调度器，单任务 `max_instances=1`；同机多个 worker 用数据库旁的文件锁互斥。部署多台服务器或独立容器时，需要保证该锁文件共享，或只在一个实例启用收信任务。
- 每次搜索最多跨越 2000 个 UID，最多获取 8 封指定主题邮件；先查询大小，超过 256 KiB 不下载正文。单封内存有界，使用 `BODY.PEEK[]`，不标记已读、不移动、不删除邮件。
- IMAP 单次网络操作超时 15 秒，单次 DNS 查询超时 5 秒；每封最多尝试 5 个签名。网络故障下一轮重试；暂时 DNS 故障保留当前 UID 等待重试，可能推迟后续邮件处理。
- UID 游标和 UIDVALIDITY 存在认证数据库中；重启可继续读取。密码更新与游标保存分开提交，崩溃后可能重新读取邮件，但一次性申请避免重复改密。
- 每邮箱每 10 分钟最多 3 次申请，每 IP 最多 10 次，全局最多 100 次；每 worker 同时最多一个找回密码哈希任务。短事务完成申请占位后释放写锁，再运行 bcrypt，避免在哈希期间占用 SQLite 写锁。
- 新密码沿用 bcrypt，至少 6 个字符且 UTF-8 编码后最多 72 字节，避免静默截断。
- 申请记录在后续申请时清理超过一小时的数据。旧 token 带 `session_id` 时会按现有机制失效；既有兼容逻辑仍允许无会话标识的历史访问 token 存活到到期，本功能没有重写全局 token 校验。
- 本地实测不代表生产服务器 2 核、2 GB 上的性能保证，发布后应关注任务耗时、认证数据库锁等待和邮箱积压。

## 验证

聚焦测试（导入期间的数据库初始化也重定向到临时目录）：

```bash
.venv/bin/python scripts/run_password_reset_tests.py
```

覆盖申请、错误码、密码快照、账号状态、过期、重放、会话撤销、真实密码哈希、签名验证、正文篡改、伪造认证头、DNS 重试、读取游标、批量上限和邮件大小上限。

2026-11-10 已完成真实 Gmail → QQ IMAP 验证：用户发送测试邮件，独立 DKIM 验签成功；另一封带申请编号的邮件使临时数据库中的隔离账号完成重置，新密码有效、旧密码无效，再次扫描没有重复重置。没有修改真实用户账号，也没有部署到生产服务器。授权码没有写入代码或文档。

本地再次读取并验签该真实邮件的单轮实测耗时 0.717 秒，`tracemalloc` 记录的 Python 分配峰值约 220.1 KiB；重放没有触发改密。这不是进程总内存或生产服务器性能测量。

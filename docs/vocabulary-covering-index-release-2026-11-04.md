## 生产执行与保护

先只读确认了 WAL、UID1000、四个既有索引、id 为 INTEGER PRIMARY KEY、DB/WAL 大小稳定，日志尾部未见词表写请求。服务器剩余磁盘约5.3GiB。Docker 限制实际是1.5 CPU / 1.5 GiB；检查时 cgroup memory usage 1190932480 字节，failcnt=0。

执行脚本只通过 SSH stdin 传入内存，没有在服务器落地分析脚本或数据库副本，没有业务 API 重放、ANALYZE、VACUUM、主动 checkpoint、配置变更或重启。

迁移保护：

- 一个 SQLite 执行线程，nice19；连接页缓存1MiB、mmap=0、temp_store=FILE、threads=0、wal_autocheckpoint=0、争锁等待100ms；这些都是迁移连接设置，不是生产全局配置。
- 进程虚拟地址上限96MiB，CPU时间软/硬限10/12秒。
- 启动要求宿主可用内存>=192MiB、剩余磁盘>=512MiB；运行中宿主可用内存<128MiB退出。
- 最终版本另要求容器余量启动>=128MiB、运行>=64MiB。
- 独立宿主看护读取内存、swap、新完成的词表写请求；swap增加>4MiB或观察到词表写请求则中断。没有可靠的“尚未完成写请求”与全链路延迟实时指标，不声称可观察它们。
- 通过随机nonce、NSpid、启动时间确认准确宿主PID，确认后才发送USR1允许DDL启动；看护直接向该PID发信号，不依赖Docker客户端信号转发。预算+1秒发INT，1秒后仍运行则发KILL；异常退出后必须独立核对最终提交状态。无法承诺内核不可中断I/O在固定时间内立刻退出。

维护脚本在本地额外验证了：已有正确索引跳过、错误同名索引拒绝、写锁冲突退出、超时回滚且原记录保留、容器内存余量不足拒绝；看护握手成功、忽略INT的进程在约6.1秒被外部KILL。完整副本在最终脚本下本地建索引约0.98秒、RSS约18.1MiB。复制完整文件造成的页缓存也计入容器内存，因此最终完整副本测试使用本地384MiB容器以保留128MiB启动余量，并没有提高生产容器限制。

## 尚未完成及下一步

生产索引尚未建立，也没有把本地前后端发布到生产。因为缺少新索引，即使先发布后端，也会正确降级旧路径，不能期待上述覆盖扫描收益。

要继续建索引，需要一个允许更长词表写锁的维护窗口。WAL查询通常可继续，但CREATE INDEX持有写锁，超过现有10秒busy_timeout的词表写请求可能失败；不能把延长预算描述为零影响。应先明确允许的写入暂停窗口，再调整一次性迁移预算和看护，保持相同内存/CPU/失败保护，完成后核对真实索引和执行计划。不建议未经确认改用不受限在线DDL。

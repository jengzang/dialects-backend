# 首页蜘蛛、蚯蚓快捷查询预热测量

日期：2026-10-27。默认永久结果由七份增加至九份，新增蜘蛛卡片第一页和蚯蚓地图详情。前端调用不变。

后续更新：用户确认删除前端未使用的 standard-words limit=100 主动预热，当前为八份。下述三轮测量保留为九项版本的历史记录。删除后同机单次复测：八项冷预热 1.2248 秒、有效结果检查 5.1 ms、Redis 数据 key 合计 182,312 字节（约 178.0 KiB）、进程峰值 RSS 117.22 MiB，较预热前峰值增加 36.02 MiB。100原为1000的派生结果，删除后实际数据库查询仍为八次，不能从不同轮次耗时推断加速或变慢；确定减少的缓存占用为 12,552 字节。当前相关测试80项通过，独立定点复核通过。

## 测量方式

- 环境：macOS 26.3.1 arm64 开发机，Python 3.12，Docker Redis 7；不是生产 2 核 2 GB 服务器。
- 数据：本地 `data/vocabulary.db`，95,003 条 vocabulary_entries，以 SQLite `mode=ro` 打开；无数据库写入。
- Redis：127.0.0.1:16379，临时容器、64 MiB 上限、无持久化。每轮独立随机 namespace，结束仅清理自身 key，不执行 FLUSHDB/FLUSHALL。
- 顺序运行三次独立进程，使用实际 `warm_once`、服务层查询和资源准入逻辑。每轮 Redis 默认结果为空，但操作系统文件缓存未清空，不能当作磁盘完全冷启动结果。
- 计时包含默认 key 检查、八次数据库服务调用、Redis 编解码与七次 100 ms 让出间隔；不含上传、通知后的 1 秒合并等待、生产网络和资源竞争。

## 结果

| 指标 | 第一次 | 第二次 | 第三次 |
| --- | ---: | ---: | ---: |
| 九份结果完整预热 | 1.0671 s | 0.9816 s | 1.0273 s |
| 全部有效时检查 | 2.8 ms | 9.4 ms | 4.6 ms |
| 蜘蛛 entries 查询 | 15.5 ms | 16.4 ms | 28.3 ms |
| 蚯蚓 map-items 查询 | 4.4 ms | 0.7 ms | 0.9 ms |
| 进程峰值 RSS | 117.12 MiB | 117.19 MiB | 117.08 MiB |
| 相对预热前峰值增量 | 36.14 MiB | 36.28 MiB | 36.08 MiB |

九个永久 key 的 MEMORY USAGE 合计 194,864 字节，约 190.3 KiB。蜘蛛 key 为 12,552 字节、蚯蚓 key 为 14,600 字节，两项共增加 27,152 字节，约 26.5 KiB；这些只是数据 key 的 Redis 占用，不包含状态与租约元数据。

同机原七项配置的单次参考测量为 0.7669 秒、167,712 字节。增加两项不会新增后台并发，新增成本主要为两次 100 ms 查询间隔及实际查询、序列化开销。九项结果的三轮中位预热时间为 1.0273 秒。已有全部有效结果时不重跑数据库查询。

## 资源和更新语义

- 沿用跨 worker 的单库预热锁，逐项执行；map-items 与在线查询一致，使用单个 expensive 资源槽及已有 heavy 准入。没有新增进程、线程池或并行查询。
- 后台遇到在线任务占用资源时会让出并稍后继续；entries/locations 版本变化会中止旧任务的后续查询，旧结果不得进入新版本。
- 数据更新后先等待约 1 秒合并通知，再进行预热；空闲环境按本次测量约 2 秒后完成。若有资源竞争、连续写入或 Redis 故障，耗时会增加，不能据此给出生产完成时间上限。
- 新增结果不设置 TTL，也不占按需 LRU 的名额；其他页码、搜索字段和筛选组合仍按需缓存一小时。永久结果内存随实际数据增长；本次两项未使进程内存出现明显新增峰值，但不能据此认为未来数据增长没有内存成本。
- 蚯蚓 HTTP 路由显式传入 `standard_word_key=None`，规范化后与预热省略该字段的参数相同；已用真实路由禁止查库的测试验证蜘蛛、蚯蚓均直接命中预热结果。

## 验证

新增四项真实 Redis 测试覆盖 HTTP 命中、TTL、LRU 保护、entries 变化及地点坐标变化。与调度、编码、生命周期、数据库资源限制测试合计 79 项通过。

扩大运行旧缓存/写入套件时有四项已有断言失败，均假设 locations 变化只使地图缓存失效；恢复原七项配置重复运行仍是这四项失败（38 项通过）。当前业务实现已使全部搜索缓存依赖 locations 版本，本次不修改这些旧规则断言。

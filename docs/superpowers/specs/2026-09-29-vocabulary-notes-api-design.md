# 字表注释搜索：后端 API 与地点范围设计

## 状态

已确认，等待用户审阅拆分后的前端、后端两份设计说明。详细实施计划必须在两份设计均获确认后再写。

本说明只定义后端职责。路由切换、草稿/已应用范围、控件、卡片和请求失效由前端仓库的 `docs/superpowers/specs/2026-09-29-vocabulary-notes-location-scope-design.md` 定义。

## 目标与边界

新增一个公共、受限流的只读接口 `GET /api/notes`。它从 `dialects_user.db` 的 `notes` 表搜索 IPA 与注释，并支持地点、地图集分区和音典分区作为结果范围。接口为前端字表注释卡片提供稳定分页结果，也可独立调用。

本接口不修改既有词表查询、`/api/search_chars`、`/api/get_locs/` 或数据库构建流程；不接受任何客户端传入的数据库名称或路径。

`/api/search_chars` 仅是地点/分区行为的参照样本。`/api/notes` 不得导入、调用或复用它的路由或查询编排函数，避免把查字的业务耦合、返回形状和未来改动带入注释搜索。notes 服务要独立实现自己的范围解析和查询流程，并以兼容性测试锁定与 `/api/search_chars` 一致的地点/分区语义。

## 数据来源与关联

注释源表：

```text
dialects_user.db
  notes(簡稱, 漢字, 音節, 聲母, 韻母, 聲調, 註釋)
  notes_fts(註釋)  // contentless FTS5，unicode61
```

地点和分区元数据：

```text
query_user.db
  dialects(簡稱, 地圖集二分區, 音典分區, 存儲標記, ...)
```

唯一关联键为：

```text
notes.簡稱 = dialects.簡稱
```

notes 表没有地点全名、行政区、地图集或音典分区列。因此分区过滤必须先在 `query_user.db.dialects` 独立展开为简称集合，再以 `notes.簡稱` 过滤；不能在 notes 表上假设这些字段存在。

当前有效注释行（`註釋` 非空、非 `_`、非 `-`）与地点映射完全覆盖：212,102 行、2,060 个不同简称均可映射到两类分区。该事实支持全库和大分区查询，但不能作为 API 的用户地点数量上限。

## 公共 API 合同

```http
GET /api/notes
  ?search_fields=pronunciation,detail
  &locations=广州
  &locations=香港
  &regions=珠三角
  &region_mode=yindian
  &page=1
  &page_size=50
```

| 参数 | 规则 |
| --- | --- |
| `q` | 可选。非空时搜索 IPA 或注释；空值时不做字段搜索，返回当前范围内最新的有效注释行。IPA 分支保留内部空白，注释分支移除所有 Unicode 空白。 |
| `search_fields` | 可重复或逗号分隔；仅允许 `pronunciation`、`detail`、`all`。遗漏、空值或 `all` 表示两个字段；未知值或 `all` 与其他字段混用为 400。 |
| `locations` | 可重复；按 notes 服务独立实现的现有地点精确匹配语义解析。 |
| `regions` | 可重复；按 `region_mode` 的分区语义解析。 |
| `region_mode` | `map` 或 `yindian`，默认处理与 `/api/search_chars` 的公开行为一致。 |
| `page` | 从 1 开始的整数。 |
| `page_size` | 默认 50，范围 1～200。 |

响应：

```json
{
  "items": [
    {
      "id": 519,
      "location_name": "1883廈門",
      "character": "□",
      "ipa": "lo3",
      "notes": "高,原文作“高”白读,应为训读"
    }
  ],
  "total": 1,
  "page": 1,
  "page_size": 50
}
```

`id` 是原始 `notes.rowid`；`location_name`、`character`、`ipa`、`notes` 分别来自 `簡稱`、`漢字`、`音節`、`註釋`。源行没有按展示值合并的语义。

## 地点范围语义

1. notes 服务独立对显式地点执行现有的精确匹配行为，并按 `region_mode` 独立展开系统分区标签。
2. 显式地点与所有选中分区取并集；同名裸分区标签的并集行为保持与现有查询一致。
3. 没有任何 `locations` 或 `regions` 参数时，不加入地点条件，搜索全库有效注释。
4. 只要请求提供过任一范围参数、但独立解析后没有任何简称，直接返回空分页结果；绝不能省略地点条件后退化成全库。
5. 个人自定义分区不作为 API 参数。前端会先将其展开为 `locations`，后端按普通显式地点处理。
6. 接口不设用户角色或业务性的地点数量上限。分页只限制单页网络传输和渲染量，不截断地点范围。实现仍须去重地点并安全处理数据库参数规模，不能用前端限额掩盖性能问题。

为了保持行为一致性，后端测试应针对同一组地点/分区输入比较 notes 服务与 `/api/search_chars` 的公开地点范围结果；实现本身保持独立。

## 搜索语义

仅搜索 `TRIM(COALESCE(註釋, ''))` 不为 `''`、`'_'`、`'-'` 的 notes 行，IPA 搜索也不能返回这些注释哨兵行。

### IPA：`pronunciation`

- 使用字面子串匹配，不解释用户输入为通配符。
- 转义 `\\`、`%`、`_`，以 `LIKE '%' || :ipa || '%' ESCAPE '\\'` 查询 `音節`。

### 注释：`detail`

- 将查询词的全部 Unicode 空白移除。
- notes FTS 构建时将注释每个字符以空格分隔；因此把 `文白` 规范为带引号的 FTS5 短语 `"文 白"`。
- 先转义用户输入的双引号，再构造短语。`文白` 和 `文 白` 都应命中存储的 `文 白`，但响应保留源注释文本，不做规范化展示。
- 必须支持一个或两个汉字的注释词。

当两个字段同时启用时，以两个命中 `rowid` 集合的 `UNION` 合并，而不是 `UNION ALL` 或显示列的 `DISTINCT`。这样同一源行命中两种字段时只返回一次，不同源行即使显示相同也都保留。

非空关键词的搜索结果固定为 `ORDER BY notes.rowid ASC`。空关键词没有时间字段可排序，“最新”定义为 `ORDER BY notes.rowid DESC`，即数据库中最后写入的有效源行优先。两种路径的 `total` 与分页项目必须来自同一 matched-row 集合；不能在 FTS 命中集和实际返回集之间采用不同的有效注释或地点范围条件。

## 服务、路由与安全

- 新建独立的 notes 路由/服务边界；不要把 endpoint 挂到现有 vocabulary 查询实现中，也不要改变 `/api/search_chars` 的响应或逻辑。
- 使用服务器固定的 `dialects_user.db` 和 `query_user.db` 配置，SQLite I/O 在既有线程池/连接池模式下执行。
- 在公开 API 配置中为精确 `/api/notes` 路径添加公开且受限流的规则，优先级高于任何宽泛匹配规则。
- 对页码、页大小和字段名进行显式验证；空关键词是受支持的最新数据浏览请求。连接、FTS 或数据库故障沿用项目统一错误处理。
- 不新增数据库迁移、FTS 重建、数据库选择、count、地图、自动补全或分区树接口。

## 后端验收与测试

- 服务测试覆盖空关键词按 `rowid DESC` 的最新数据分页、1 字、2 字、`文白`/`文 白`、IPA 字面 `%`/`_`、空/`_`/`-` 注释排除、双字段单源行、相同展示值的不同源行、稳定分页与总数。
- 地点范围测试覆盖无范围全库、显式地点、地图集分区、音典分区、地点与分区并集、重名标签并集和范围零解析返回空。
- 路由测试覆盖 `/api/notes` 注册、公开但受限流、请求参数验证和响应模型。
- 使用临时 SQLite/FTS5 fixture 验证精确 SQL 行为；再针对真实数据库的全库及大分区场景做分页和性能回归，不设置地点数量上限来规避问题。

## 非目标

- 不修改或复用 `/api/search_chars` 的查询编排函数。
- 不修改 `/api/get_locs/`、既有词表接口或 notes FTS 构建逻辑。
- 不增加分区路径值、补齐前端顶层树或引入客户端数据库选择。

## 改动

- 标准词聚合直接迭代 SQL 游标，不再 fetchall；只保留最近词形的归一键，去掉整张请求内词形映射。有限 limit 用堆选，全量仍完整排序。跨请求简繁转换 LRU 最多 8192 项，变体缓存沿用 4096 项。
- entries 的精确 total 按完整计数 SQL/绑定参数单独缓存，不含分页条件；使用现有 Redis 缓存上限、租约和词条/地点版本栅栏，跨页复用并在写入后失效。SQL 编辑器原查询接口的分页计数不在这项缓存复用范围内。
- COUNT 仅在过滤条件引用地点别名 `l.` 时保留 JOIN。地点文本搜索会搜地点元数据，依然保留；地区子查询的身份过滤继续保留。数据查询继续关联地点以生成标签，不会因此丢失返回字段。
- 地图点查询先对窄的词条身份聚合，再取地点元数据；涉及地点字段的过滤仍在聚合前正确执行。
- 上传直接使用 UploadFile 文件对象；原文件复制按 1 MiB 缓冲，解析行暂存磁盘。CSV/TSV 每 512 行读取，XLSX read_only 逐行读取；保留数字、空白、重复标题和 Excel 错误单元格的既有行为。
- 导入每 512 行插入，但全部替换和日志仍一次事务提交。旧词条日志快照最多物化 501 条，以判断 500 条日志保留上限；真实删除/导入数量没有上限或缩减。
- 上传预览、4 个 SQL 修改/预览入口、导出生成使用有界后台工作单元。提交和缓存通知在同一个工作单元内执行，断开/重复取消会等待线程结束才释放资源。
- 批量替换只按每批 256 行读取必要字段。新事务先验证，再 BEGIN IMMEDIATE；锁内复核 SQLite data_version，验证期间发生其他连接提交则回滚并返回 409。已有事务保留 SQLite 自身的快照/锁升级保护。提交、日志及既有部分成功规则保持原样。
- XLSX 导出写入临时文件，再按文件分块传输；生成异常、发送失败和正常完成会清理临时文件。保持原文件名、表头、全部数据及 Content-Disposition。

## 2 核 2 GB 资源约束

- 地名与词表实际重计算共用原有 **全机 2 个 heavy 槽**，通过 POSIX flock 跨 worker 生效；Redis 故障回源也走同一准入路径。
- 词表 standard-words、map-items、导入解析、预览和导出生成另共用 **1 个高内存作业槽**。
- 本次导入及 SQL 修改入口每数据库 **1 个写作业槽**。其他原有地点/权限等同步修改入口仍依赖 SQLite 原有事务锁，不宣称所有后台写路径已统一改造。
- 全机最多 **8 个词表准入等待者**；等待最多 30 秒，超出返回 503/Retry-After。限制的是未开始的工作；已接受的完整结果计算没有新增总执行时限，不会以超时伪装成成功的半份结果。
- 后台线程复用既有 asyncio 线程池，先准入再派发。进程结束会释放 flock，锁文件不删除，以免破坏跨进程互斥。
- 修改不做自动重试。409 要重新预览/确认当前数据；503 可稍后退避重试。事务失败回滚，临时文件在 finally 清理；预热沿用现有有界退避。
- 临时磁盘空间随上传文件、暂存行及尚在下载的导出文件增长。部署须保证 TMPDIR 位于有空间的磁盘；若挂在 tmpfs，仍会消耗机器内存。磁盘不足会明确失败并清理可清理文件，没有静默少导入/少导出。

## 实测：全部标准词，不截断

使用只读真实库生成独立临时数据库；95 万条记录，索引结构保持一致。每个版本单独进程，Python 3.12 / SQLite 3.53.2，直接调用现有服务函数，`limit=None`。记录进程峰值 RSS，并对完整有序结果逐项更新 SHA-256，包含全部字段。

| 临时数据 | 全量分组 | 原版本峰值 RSS / 耗时 | 新版本峰值 RSS / 耗时 |
|---|---:|---:|---:|
| 增加地点，词形不变 | 39,965 | 303.9 MiB / 0.590 s | 207.6 MiB / 0.547 s |
| 地点与不同词形均增长 | 399,650 | 597.8 MiB / 2.201 s | 515.4 MiB / 2.158 s |

两组原/新版本各自全部结果摘要完全一致：

- 39,965 组：`43d7743c29a72f09c49e10b10ce4b3be347995fcdb3691086d7d5c7f0eb593f0`
- 399,650 组：`c7e1bea6242ac2680a87feaccc9c6940678f6d43c21a4d20e8451ff8bb8b6137`

这是本机单次观测，不是生产延迟、吞吐或整机占用保证，也没有包含 HTTP/Redis/前端渲染成本。完整分组字典、地点集合、最终结果对象仍随数据增长；本次减少中间复制并限制并发，没有把任意规模的归一聚合变成常数内存。继续增长时仍需评估磁盘中间聚合或事务性汇总表。

CSV 暂存的补充本地 tracemalloc 测量：1 万/10 万行 Python 分配峰值约 1.23/2.01 MiB，约 0.147/1.495 秒。它不是进程 RSS，不能与上表直接比较。

使用隔离临时 Redis 7.2.6（仅回环地址、禁用持久化）执行缓存集成测试。没有依赖生产 Redis。

完整词表 + 地名相关套件结果：**283 passed，10 failed**。10 个失败在改动前的归档版本均已复现；归档版本词表套件为 201 passed、12 failed，另外 2 个是旧上传测试仍 monkeypatch 已不存在的 redis_client，现已改为通知接口并使用真实 UploadFile/跨线程可用的内存 SQLite 测试夹具。

1. 缓存旧测试有 4 项期待地点版本变化不影响 entries，但当前实现早已让 entries 依赖地点版本，以维护地点标签等字段；本次精确计数也保留这个正确的依赖。

这些旧失败没有通过修改生产语义或删减断言来掩盖。排除以上已确认的旧失败后，运行全部其余相关测试验证本次变化；具体命令与结果由本次工作记录保留。新增测试、前端契约、全量摘要以及独立规格/质量复核均已通过。
